## 总览

```
+---------------------+
| "KSD1"   (4 字节)   |  魔数（明文）
+---------------------+
| 命令流 ...          |  命令字(2 字节明文) + 各命令参数
+---------------------+
```

**头部只有 4 字节。**
`FUN_00413a70` 读 4 字节校验魔数 `0x3144534b`（"KSD1"）后立即返回；随后
`FUN_00413b60`（分派主循环）从第 5 字节开始读 2 字节命令字。

> ⚠️ **旧模型错误**：早期把头部当成 10 / 18 字节，导致正文起点错位 6~14 字节，
> 全部文本错位、资源路径读不出来。该模型已废弃。

## 编码规则

| 区域 | 编码 |
|---|---|
| 命令字 | 明文 16 位小端 |
| 数字参数 | 明文 16 / 32 位小端 |
| 字符串长度前缀 | **明文** 16 位小端 |
| 字符串内容 | **XOR 0xFF** |
| 资源路径 / 文件名 | **XOR 0xFF** |

关键点：**所有字符串都有明文 2 字节长度前缀**，只有内容本身是 XOR。
旧「零消费模型」以为字符串是裸文本流，导致读参数时把参数当文本吃掉。

## 场景切换（命令 10）

```
| 2 字节长度 | N 字节文件名(XOR) |
```

`FUN_00405840` 读到文件名后：关闭当前流 → `FUN_00413a70(文件名)` 递归加载新场景。
所以场景跳转是**由剧本自身驱动**的，不是硬编码。
